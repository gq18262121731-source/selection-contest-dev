## 1. 功能范围

本阶段实现“机器狗跟随监看与遥控器协同”，包括：

- 社区工作台独立导航与 Hash 路由；
- Go2 MJPEG 第一视角监看、失败原因和手动重连；
- “登记跟随请求 / 撤销请求记录”网页会话意图，明确标注未发送至机器人；
- 随行遥控器同步操作和安全提醒；
- 当前用户级 `go2bridge://start` Windows 协议；
- “启动本机视频服务”按钮、启动阶段快速轮询和后台指数退避检查；
- 服务稍后启动、页面恢复前台或浏览器网络恢复时自动恢复画面；
- 可折叠的视频诊断信息，包括帧龄、帧率、地址、重连次数和服务版本；
- 桌面、平板与窄屏布局。

本阶段不调用 Go2 站立、移动、停止或其他运动控制接口，也不把网页标记解释为机器狗真实状态。

## 2. 页面状态与安全语义

| 场景 | 预期结果 |
| --- | --- |
| 首次进入 | 跟随状态为“未确认”，页面探测本机 `8093` 服务 |
| 点击“登记跟随请求” | 进入 `REQUESTED` 本地意图态，并明确显示“未发送至机器人”；不得解释为机器人已接受或执行 |
| 点击“撤销请求记录” | 恢复 `IDLE`，仅清除当前页面记录；不会向机器人发送停止指令 |
| 页面重新加载 | 清空网页状态和操作记录，恢复为“未确认” |
| 视频服务离线 | 显示“视频服务未启动”和本机启动按钮 |
| 点击本机启动按钮 | 当前页面保持在 `#/robot-follow`，调用 `go2bridge://start` 后轮询 `/status` |
| `data.hasFrame=true` | 为 `/stream.mjpg` 增加时间戳并在当前页面重新加载画面 |
| 启动阶段没有画面 | 区分“服务未启动”和“服务在线但无帧”，随后继续后台退避检查 |
| 服务稍后自行恢复 | 页面无需刷新或点击，自动重建 MJPEG 连接 |
| 页面回到前台或网络恢复 | 立即请求一次 `/status` |

跟随状态不写入 `localStorage` 或 `sessionStorage`。视频服务启动与自动跟随控制彼此独立。

## 3. 本机启动链路

```text
社区端“启动本机视频服务”
        ↓
go2bridge://start
        ↓
当前用户 HKCU 协议处理器
        ↓
Go2VideoBridgeLauncher.ps1
        ↓（固定参数 -NoOpenBrowser）
start_sta_wireless.ps1
        ↓
127.0.0.1:8093 视频桥接服务
        ↓
当前 #/robot-follow 页面轮询 /status
        ↓ data.hasFrame=true
当前页面重新加载 /stream.mjpg
```

协议处理器只接受 `start` 和只读 `status`，拒绝查询参数、可执行文件路径、命令行和任意脚本参数。启动脚本以 `-NoOpenBrowser` 运行，因此不会打开额外预览页或浏览器标签页。

安装和卸载方法见 [本机启动器说明](../tools/go2-video-bridge-launcher/README.md)。安装时必须显式传入已审核的 `start_sta_wireless.ps1`，安装器不依赖开发电脑的固定盘符或项目目录。

## 4. 接口说明

本次没有新增服务端业务接口，复用本机视频服务的只读接口：

| 地址 | 请求方式 | 请求字段 | 关键返回字段 | 用途 |
| --- | --- | --- | --- | --- |
| `/status` | GET | 无 | `apiVersion`、`serviceId`、`timestamp`、`data.videoState`、`data.hasFrame`、`data.lastErrorCode` | 判断服务身份、画面状态和错误类型 |
| `/stream.mjpg` | GET | 无 | MJPEG 字节流 | 当前页面持续显示视频 |

`/status` 新增 v1 顶层版本、服务身份、时间戳，以及服务状态、视频状态、最后帧时间、结构化分辨率、来源、客户端数量和错误代码。原有 `success`、`connected`、`hasFrame`、`captureFps`、`lastError`、`latestFrame` 等字段全部保留，兼容旧页面。CORS 继续使用精确开发环境白名单。

## 8. 当前真实联调结果

### 8.1 连续 15 分钟播放

结论：通过。

- 持续时间：`900.5` 秒；
- 采样次数：`30` 次；
- 失败或非健康样本：`0`；
- 最大帧龄：`125 ms`；
- 观测帧率：约 `8.62–8.68 FPS`；
- 帧计数增量：`7589`；
- 测试期间错误增量：`0`；
- 测试期间重连增量：`0`。

### 8.2 运行期间视频异常自动恢复

结论：通过。

测试期间捕获到以下状态迁移：

```text
视频正常
→ FRAME_STALLED
→ WEBRTC_DISCONNECTED
→ WEBRTC_CONNECT_FAILED
→ 后台自动重试
→ 视频重新出帧
→ 页面恢复就绪
```

`18:47:59` 至 `18:48:26` 之间发生约 `27` 秒连续停帧。恢复过程未刷新页面、未点击“重连视频”，也未重新操作本机启动器。最终状态为 `connected=true`、`hasFrame=true`、`frameAgeMs=171 ms`、`lastErrorCode=null`；实际画面为 `1280×720`，最后 5 秒增加 `42` 帧，约 `8.4 FPS`。视频恢复没有产生跟随操作记录。

`reconnectCount=41` 是视频服务进程生命周期累计值，不能解释为本轮发生 41 次独立断线。后续状态契约宜拆分重连尝试数、成功数和当前退避时间。

### 8.3 Go2 严格冷启动恢复（单轮）

结论：单轮通过。

测试期间社区后端、Vite 前端、`8093` 视频服务和 `#/robot-follow` 页面始终保持运行，仅关闭并重新启动 Go2。用于证明服务未重启的进程信息为：

| 服务 | 进程 ID | 启动时间 |
| --- | ---: | --- |
| 社区后端 `8000` | `12104` | `18:38:01` |
| 社区前端 `5173` | `26260` | `18:36:33` |
| 视频服务 `8093` | `18116` | 进程 `18:31:38`，服务 `18:31:40.778169` |

Go2 恢复后的首个完整快照为 `videoState=ready`、`connected=true`、`hasFrame=true`、`frameAgeMs=63 ms`、`frameCount=27560`。随后约 42 秒共采集 15 个样本，全部为 `ready`，最大帧龄 `141 ms`，帧计数增加 `376`，约 `8.9 FPS`，错误数和重连数没有继续增加。最终帧龄 `16 ms`、帧计数 `28988`，页面自动恢复 `1280×720` 画面，未刷新、未点击启动或重连按钮，跟随操作记录仍为 0 条。

`reconnectCount=111`、`errorCount=86` 同样是进程生命周期累计值。由于本轮采样开始时链路已经恢复为 `ready`，没有捕获从 Go2 网络恢复到首帧的精确时延。
