# 智慧康养 AIoT 多模态监测与应急协同方案（当前项目一页版）

## 项目定位

本项目面向居家与社区养老场景，以老人安全和健康风险为核心，已经形成“可穿戴设备与摄像头感知—后端融合判断—多端实时告警—智能体分析解释—机器狗现场处置”的完整技术闭环。系统服务社区工作人员、老人及家属，可用于日常健康监测、SOS 求助、跌倒识别、风险研判、应急协同和周期性健康报告，并兼顾比赛现场的稳定演示与真实设备扩展。

## 四大核心模块

| 模块 | 当前已有组成 | 当前核心能力与产出 |
|---|---|---|
| **一、视觉模型** | YOLO 人体/跌倒检测、YOLO Pose 17 点姿态估计、ByteTrack 多目标跟踪、YuNet + SFace 目标老人识别、姿态风险分类、GRU 时序模型、TCN + Transformer 混合时序模型、多模态大模型复核 | 对摄像头画面进行人体定位、目标老人过滤、姿态识别和连续动作分析；通过多模型融合、连续帧确认、状态机和伤害等级评估，降低把坐下、躺下、弯腰误判为跌倒的概率；输出事件 ID、置信度、风险等级、目标身份、现场快照和处置建议，并可接入主系统生成统一跌倒告警。 |
| **二、后端、数据处理与告警链路** | FastAPI 主系统、T10 手环解析、BLE/串口/MQTT/HTTP/Mock 接入、健康数据仓储、规则引擎、PyTorch 健康评分模型、动态 Z-Score、告警优先队列、WebSocket、Vue 社区端、Flutter 老人/家属端 | 接收心率、血氧、血压、体温、步数、电量和 SOS 等数据，完成双包合并、校验、清洗、补齐、持久化和趋势聚合；通过“规则 + 模型 + 时间窗口稳定化”输出健康分、风险等级和异常标签；将 SOS、生命体征异常、智能异常和视觉跌倒统一进入告警中心，具备去重、持续按键抑制、确认冷却、优先级排序、实时弹窗和多端展示能力。 |
| **三、具身智能机器狗** | Unitree Go2、Robot Gateway 契约、机器人状态与能力诊断、任务中心、建图/点位/路线/巡航接口、应急处置工作台、第一视角视频、任务回调与证据留存、安全联锁 | 跌倒事件可创建机器人应急任务，经过网关和硬件能力检查后执行前往现场、到达取证、语音询问、等待回应、结果上报和返航；主系统记录 `QUEUED—RUNNING—COMPLETED/BLOCKED` 全任务时间线，并融合 `SAFE / NEED_HELP / NO_RESPONSE / UNKNOWN` 现场结果；社区端已具备状态、导航、应急、视频和任务可视化页面，真实运动执行统一经过 Robot Gateway，避免前端或大模型直接调用底层运动 SDK。 |
| **四、大模型与智能体** | Qwen/DashScope 与 Ollama 适配、LangChain、LangGraph、RAG 本地知识库、工具调用、健康分析服务、社区智能体、康伴机器狗智能体、ASR/TTS/Omni 多模态交互 | 基于真实健康数据、历史趋势、告警记录和模型结果开展单老人分析、社区风险排序、告警摘要、健康解释、处置建议和周期报告生成；支持流式回答、工具调用轨迹、图表/表格/报告附件及知识库检索；康伴智能体可融合老人健康状态、天气和机器人状态进行意图理解、行动规划与安全校验，并通过语音与老人自然交互。 |

## 四模块协同闭环

```text
手环生命体征 / SOS + 摄像头视频
        ↓
数据清洗、身份关联、规则与模型融合判断
        ↓
统一告警中心 + WebSocket 实时推送 + 社区端/家属端展示
        ↓
智能体结合历史数据和知识库生成风险解释与处置建议
        ↓
高风险事件创建 Go2 应急任务，现场取证、语音确认并回传结果
        ↓
告警升级或人工确认，沉淀时间线、证据和健康报告
```

## 当前成果与方案价值

项目当前已具备可运行的后端主系统、社区 Web 看板、Flutter 移动端、手环与摄像头接入链路、跌倒多模型融合、统一告警中心、健康/社区智能体以及 Go2 任务与应急协同工作台。方案的核心价值不是单点模型展示，而是把“发现风险、判断风险、通知相关人员、解释原因、派出具身设备、回收现场证据”串成可追踪的闭环，从而同时提升老人安全响应速度、社区值守效率和家属获得感。

> 当前实施边界：外部大模型、真实消息推送、视觉服务和 Go2 真实运动能力依赖现场配置与对应服务可用性；网页中的跟随或规划状态不等同于硬件已经执行，真实动作必须通过能力检查、安全联锁和 Robot Gateway。
