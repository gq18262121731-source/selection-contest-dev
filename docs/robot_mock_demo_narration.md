# 机器人 Mock 比赛演示讲解顺序

> 建议时长：4–6 分钟。所有涉及机器人运动、地图、点云和语音的展示均为 Mock。

## 比赛现场口述版

### 第一部分：机器人状态（约 50 秒）

打开“机器人状态”页后说：

“这是健康监护系统中的机器人执行端。当前为模拟导航环境，真实机器人运动控制已禁用。页面把网络、网关、DDS、LiDAR、定位、地图和急停放在同一个只读视图中；未验证的项目只显示‘未验证’，不会误报为故障或已就绪。”

指向安全联锁：

“机器人任务每次启动、继续和返航前都必须通过七项安全检查。任何条件不满足，系统会明确显示中文阻断原因，不提供绕过入口。”

展示视频小窗后切换到“建图巡航”。

### 第二部分：建图巡航（约 90 秒）

打开“建图巡航”页后说：

“这里展示的是固定场景的模拟地图、待命点、活动区观察点和日常巡查路线。真实建图阶段将由操作员使用遥控器手动带机器人扫描；页面本身没有方向或速度控制。”

点击“启动 Mock 巡逻”，再点击“申请遥控接管”：

“现在管理员取得控制权，导航任务进入暂停。”

点击“释放控制权”，停顿并指向提示：

“释放遥控器后任务不会自动恢复，必须由管理员点击‘继续’，系统再次执行安全联锁。这避免控制权切换后机器人意外移动。”

点击“继续”并展示完成结果：

“巡逻、接管、恢复和返航都经过统一任务状态机，并写入时间线和 SQLite，形成可追踪的执行记录。”

随后切换到跌倒告警。

### 第三部分：跌倒应急（约 120 秒）

触发 `fall_confirmed`，在全局告警出现时说：

“摄像头只上报跌倒事件和区域，主系统负责区域到观察点映射，再创建高优先级机器人任务。点击‘进入应急处置’只打开详情，不会解除告警。”

依次点击“派发机器人”和“模拟到达并开始询问”：

“机器人到达观察点后进入现场询问。当前语音识别、对话理解和语音合成为模拟结果，不代表真实音频已经接入。”

选择“模拟‘我没事’”：

“老人明确回应安全后，系统仍然保持告警，等待管理员确认。”

点击“管理员确认并返回待命区”，再点击“模拟完成返航”：

“管理员确认后，返航还要再次通过安全联锁。最终案例、任务、对话、导航事件和时间线共同进入完成状态，这就是事件驱动、人机协同的应急闭环。”

### 备用分支（每项约 15 秒）

- 老人请求帮助：机器人保持原地，升级人工处置，禁止返航。
- 15 秒内无有效回应：保持告警，禁止返航。
- 无法可靠判断：不强行结束流程，等待人工判断。
- 定位无效或地图未加载：安全联锁阻止机器人出动。

### 收尾（约 20 秒）

“当前完成的是机器人导航与应急处置的软件架构、任务闭环和模拟验证。下一阶段将按点云、定位、建图、导航逐级接入真实硬件；在通过安全验收前，不把模拟结果描述为真实自主导航能力。”

以下内容保留为答辩追问时的技术补充。

## 主线讲解

### 1. 从健康感知到任务决策

“固定摄像头负责发现跌倒并上报 `fall_confirmed`。摄像头只描述 `area_id` 和 `area_name`，不携带机器人坐标，也不直接控制机器人。”

“智慧养老主系统负责告警联动、区域到观察点映射和机器人任务创建。这样感知与执行解耦，摄像头故障不会绕过任务中心直接驱动设备。”

### 2. 安全联锁先于出动

打开 `#/robot-status`：

“每次启动、继续或返航前，系统统一检查机器人在线、急停清除、定位有效、地图加载、路径可规划、机器人静止、控制权可用七项条件。任何一项失败都会形成可追踪的 blocked 任务，不提供绕过按钮。”

指出页面上的：

- `provider=mock`
- `real_motion_enabled=false`
- 七项联锁
- REST 与 WebSocket 连接状态

### 3. 地图、点位与巡逻

打开 `#/robot-navigation`：

“当前使用固定 Mock 地图。主系统保存业务点位：待命区、老人活动区观察点和三个巡逻点；Gateway 保存 Mock 执行态、安全联锁和控制权。”

启动巡逻：

“任务进入 `navigating`。现在模拟管理员接管，任务进入 `paused_manual`。释放控制权后不会自动恢复，必须点击继续并重新执行安全检查。”

继续并完成：

“Mock Gateway 返回到达和返航结果，主系统按冻结状态机持久化 timeline 与 navigation events，最终为 `completed`。”

### 4. 跌倒应急闭环

进入 `#/robot-emergency?incidentId=...`：

“主系统根据 `elderly_activity_area` 找到观察点，创建高优先级应急任务。机器人到达后，Mock 对话依次经过 `arrived → voice_prompting → waiting_response`。”

强调：

“这里的提示文本、ASR 和 TTS 都是 Mock 状态，不会伪装成真实音频播放或识别。”

选择 safe_response：

“老人明确表示安全后，系统仍不会自动解除告警。管理员必须确认，再次通过七项联锁，才允许进入返航。Mock 返航完成后，案例、任务、timeline、对话和导航事件共同闭环。”

### 5. 升级分支

依次简要展示 need_help、no_response、uncertain：

“三类情况都进入人工升级，机器人保持原地，没有返航按钮，接口也拒绝 resolve-and-return。系统优先保证现场安全，而不是为了流程完整强行结束告警。”

### 6. 可追踪与恢复

“REST 提供当前快照，WebSocket 提供增量事件；服务重启后从 SQLite 恢复任务和案例。多页面共享主系统的单上游代理，最后一个订阅者离开后释放连接。”

“本轮自动验收记录了 65 次 REST、187 条 WebSocket 摘要和 12 张页面截图，且正式 `app.db` 哈希未变化。”

## 结尾

“当前冻结的是面向健康监护的机器人协同业务合同，而不是真实自主导航能力。下一阶段会通过新增 Provider/适配层接入 Ubuntu 22.04、ROS2 Humble、L1 点云、IMU、里程计、TF、SLAM Toolbox 与 Nav2，不直接破坏已稳定的前端和主系统合同。”

## 禁止宣称

演示中不得声称：

- 已使用真实 ROS2、Nav2 或 SLAM；
- 已读取真实 L1 点云；
- 已完成真实 Go2 自主导航或返航；
- 已使用真实讯飞 ASR/TTS 或 Go2 音频；
- Mock 三维点云代表现场雷达精度；
- `mappingPrerequisitesReady` 等同于可投入自主导航。
